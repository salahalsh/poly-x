# Release notes: the JCAMD revision

This release accompanies revision 1 of the POLY-X manuscript submitted to the
*Journal of Computer-Aided Molecular Design*. The tag matching that manuscript
is `v1.0.0-jcamd-r1`.

Both referees asked for the same thing in different words.

> Reviewer 1, section 1.9: "the repository currently appears immature: it has
> only one commit, no releases, no packages, no CI, no tests, and no issue
> history. For a platform paper, the authors should provide a tagged release
> corresponding exactly to the manuscript, installation tests, unit tests for
> PSMILES parsing and group matching, regression tests for the reported
> numerical examples, and a reproducibility script for every figure and table."

> Reviewer 2, major point 13: "A versioned archival release should contain all
> source code, model artifacts, data hashes, canonicalized input data, split
> assignments, raw outputs underlying every table and figure, automated tests,
> and a one-command reproduction workflow."

## Where each item lives

| Asked for | Where it is |
|---|---|
| Tagged release matching the manuscript | tag `v1.0.0-jcamd-r1` and the GitHub Release built from it |
| All source code | `poly_x/services/` (the modules the deployed platform runs), `poly_x/training/` (what produced the checkpoints), `paper/analysis/` (what produced every number) |
| Unit tests, PSMILES parsing | `tests/test_psmiles.py` |
| Unit tests, group matching | `tests/test_group_matching.py` |
| Regression tests for reported numbers | `tests/test_regression_reported_numbers.py` |
| Reproducibility script for every figure and table | `reproduce.py`, thirteen steps including the Figure 1 schematic |
| One-command reproduction workflow | `python reproduce.py` |
| Continuous integration | `.github/workflows/ci.yml`, Python 3.11 to 3.13 |
| Canonicalised input data | `poly_x/data/tg_training_data.csv`, CC BY 4.0, attribution in that directory |
| Split assignments | `paper/outputs/s01_split_indices_seed*.npz`, `s01_cluster_split.npz`, `s02_splits.npz` |
| Raw outputs behind every table and figure | `paper/outputs/`, including all archived model runs |
| Model artifacts | attached to the GitHub Release, see below |

## Notes on two deliberate choices

**Trained checkpoints are Release assets, not repository files.** The four
prediction heads total about 55 MB. Attaching them keeps a clone small while
leaving them one click away. The fingerprint and embedding matrices are not
distributed at all: `reproduce.py` regenerates them deterministically, and the
resulting embedding files are committed under `paper/outputs/` anyway.

**Figure images are not committed; their provenance sidecars are.** Each
figure writes a `.provenance.txt` naming its input files and sample count, and
those are tracked. The images themselves are regenerated by `reproduce.py`.

## Tests and skips

The fast suite is 61 unit tests. The slow test reproduces the originally
submitted metrics from the vendored collection and takes about three minutes.

CI runs the suite with `POLYX_STRICT=1`, so a module the suite cannot locate is
an error rather than a skip. A skipped test reads as a pass, and a green badge
over a suite that silently ran nothing would be worse than no badge.

Two tests skip in a checkout by design: they compare the built manuscript and
its typeset figures against the archived outputs, and neither the manuscript
source nor the built images are distributed here.

## The dataset correction

The submitted manuscript and the deployed dashboard disagreed about the Tier 2
training set, which Reviewer 1 found. The models are trained on the PolyMetriX
curated Tg collection, not on PI1M. The platform source was corrected in eight
places across six files, and this repository carries the corrected modules.
PI1M appears in this work only as the pool for the prospective screen.
